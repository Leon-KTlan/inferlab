# 能力检测 HTTP、Mock 与雷达

## 实现范围

新增 `services/api/intelligence.go`（HTTP、输入/回传验证）、`intelligence_runtime.go`（可关闭且等待退出的运行生命周期）、`intelligence_radar.go`（私有分组与基线）及 `intelligence_test.go`。由主集成任务挂接 App、Config/Run 字段并隔离既有性能/分享/导出路由。

能力运行复用实验与 Run 存储，不新增数据库表或迁移；首次创建的实验与 Run 在同一个额度预留事务中插入，活跃额度/日预算拒绝会整体回滚，不留隐藏实验；复测只新增 Run 并沿用原实验；预留请求数为 10×重复次数，默认 20、最多 30，与性能运行共享单身份一个/全局四个活跃额度及每日预算。Mock reference 为 100 分，degraded 为 40 分；结果明确标记 `source_type=mock`、`result_kind=demo`，不会发外部 API 请求。

真实目标必须明确授权、HTTPS 且通过既有 SSRF 校验。API 只创建待本地 CLI 领取的任务。API Key 可存内存五分钟且只领取一次；任务本身不含密钥。未结束的真实任务在创建十五分钟后自动失败并释放活跃名额。每轮执行时窗最多约 120 秒；结果时钟允许 5 秒偏差，结束时间不能在未来 5 秒之外。

逐题记录只保存题号、轮次、通过与否、耗时和白名单错误码。回传强制任务令牌，拒绝客户端总分/额外字段、重复题、非法轮次、非有限耗时、未知错误、成功但不完整的数据；由服务端重算总分。终态写入使用 `finishLocalRun` 原子条件更新，取消和重复回传不能覆写结果。Mock 逐题落盘，取消后保留已完成部分；关闭时取消并等待其执行协程退出。

## 指标与边界

- 能力分数是本公开小题库的规则通过率；不代表人类 IQ、供应商身份或生产模型的整体能力。
- 五维分数以计划题数为分母；错误与缺失题不获分。只有成功、题目完整、无传输错误的结果可参与雷达比较。
- 雷达按来源、模型、规范化 endpoint、题库、重复次数和评分版本分组；Mock profile 可变用于演示，仍保留在每条运行快照中。
- 最新记录有效时，取此前最近三个有效记录的均值作为基线；不足三次历史返回 `insufficient_data`，下降至少 15 分返回 `review`，其余为 `stable`。最新失败/未完成不会产生观察信号。历史与雷达读取当前身份最近 100 条能力记录，筛选发生在数据库 LIMIT 之前。
- 普通性能指标/SLO 在能力检测中不解释。Config 的固定 workload/SLO 字段仅用于现有配额和任务结构兼容，能力报告以 `intelligence_report` 为准。
- 本地 Runner 自报结果只验证结构与一致性，服务端未独立复测模型答案。

## 验证

在 `services/api` 执行：

```sh
go test ./... -run '^TestIntelligence' -count=1
go test -race ./... -run '^TestIntelligence' -count=1
```

覆盖 HTTP 创建/隔离/默认预算/同快照复测、活跃额度与日预算 429 不遗留实验、Mock 100/40 分、取消与部分报告、日配额、性能和能力共享活跃额度、SSRF/授权、令牌与重复回传、题号/轮次/耗时/错误边界、雷达三次基线与传输错误过滤。测试通过专用内部 interval 缩短 Mock 等待；生产 interval 固定为一秒，执行上下文上限 120 秒。全量 Go 门禁与 staging/浏览器闭环由主集成任务统一执行。

## 回滚与剩余依赖

回滚前备份现有 SQLite 数据文件；关闭服务将取消并等待 Mock 协程，重启恢复逻辑会标记遗留活跃运行失败。撤销 App 路由与模型字段挂接，并恢复上一构建，无新增表迁移。旧版恢复后不得将含 intelligence 的配置交给性能 Runner；需要保留入口拒绝保护或隐藏这些模板。

尚需主集成完成实际 CLI、性能接口保护、前端和 staging 验证，之后才能标记端到端功能完成。
