# 本地 Mock 实验与样本复核

从仓库根目录执行。需要 Git、Go 和 Python 3，无需安装 Python 依赖。

```bash
python3 scripts/thesis_benchmark.py --output /tmp/inferlab-thesis-results
```

默认两组各三次。每轮各跑一组，偶数轮反转先后顺序。第一轮分别创建两个实验，后续从对应组的第一条 Run 快照复跑。每档发送窗口为 30 秒，并发上限依次为 1、4、8，RPS 上限 8，总请求上限 800，单请求超时 1 秒。两组 Mock 均不主动返回错误，预设延迟分别为 160 ms 和 420 ms。P95 阈值为 250 ms，错误率阈值为 5%。

脚本把临时构建、SQLite 和进程放在本次实验用的临时目录中，API 只监听随机本机端口。脚本只提交固定 Mock 目标，API 进程使用独立环境，实验结束后回收。Go 构建在本机缓存缺少模块时会按 Go 配置下载依赖。

## 结果与口径

- `metadata.json` 记录实验时段、OS/架构、Go/Python 版本、Git 提交和工作区是否有更改，以及二进制 SHA-256。
- `reports.json` 保存每轮报告、配置快照、场景和复跑源。两种场景分别独立报告。
- `samples.csv` 保存逐请求阶段、开始时间、耗时和错误码。脚本使用 SQLite 只读连接复核总体及各档样本计数、P50/P95、错误率、完成速率和 SLO；检查所有档位实际覆盖且重算结果与报告一致。分位数按 nearest-rank 算法取值，失败样本仍计入完成样本。完成速率的分母为报告的实际观测时长，包含阶段末尾等待。
- `stages.csv` 提供各轮、各档的原始统计。 `p95-by-stage.svg` 绘制每组各档 P95 在重复运行中的中位数和预设阈值。并发和 RPS 是参数上限，实际速率以报告为准。数据仅用于验证本机 Mock 性能测试链路。

## 快速检查与失败处理

```bash
python3 scripts/thesis_benchmark.py --help
python3 scripts/thesis_benchmark.py --output /tmp/inferlab-thesis-quick --repeats 2 --stage-seconds 1
```

快测覆盖创建、报告、同场景快照复跑和样本复算，1 秒档位允许报告为样本不足。正式实验可用 `--stage-seconds 15` 缩短等待，每档仍必须有至少 20 个样本，正常组达标、变慢组超标且两组无错误。任何验证失败会停止并返回非零退出码。输出目录必须是新路径，验证通过后才写入。失败时根据终端报错校对源码依赖、运行环境或样本结果；重跑时使用新的输出目录。该工具不修改项目现有数据库或发布配置；回滚工具本身只需移除脚本与所生成的实验产物。

开发验证已实际运行 1 秒快测，两组各两次，共生成 4 份报告（含两次复跑）、12 个阶段和可解析的 SVG。84 条逐请求样本均参与复算。该验证仅覆盖工具链路，正式结论以完整实验结果为准。
