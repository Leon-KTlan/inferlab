# 固定延迟 Mock 场景

创建 Mock 实验时可提供可选字段 `target.mock_scenario`。

| 场景 | 服务端等待 | 主动注入错误 |
| --- | ---: | --- |
| `baseline-v1` | 160 ms | 无 |
| `slow-v1` | 420 ms | 无 |
| 省略或空字符串 | 旧演示动态延迟 | 保留旧演示的 503 |

固定场景由本进程回环 HTTP Mock 实际响应。Runner 仍测量整个 HTTP 请求的客户端延迟，实测包含本地连接、调度和读取开销。场景绑定本次 Run，两个固定场景均不引用旧演示的全局请求计数；单请求超时、Run 取消和配额仍然适用。

每次运行将场景 ID 与负载、SLO 一同保存为 Run 快照。严格基线对比要求场景 ID 相同。正常与变慢两组应分别保存报告，用于同负载实验对照。若修改固定延迟或响应规则，使用新的场景 ID，使旧报告仍可解释。

未知场景、将场景传给真实目标均为配置错误。旧配置无场景字段，仍可运行。没有 SQLite 架构变更。恢复旧构建后，使用省略场景字段的实验模板继续运行；依赖新场景的实验应在支持其语义的构建上复跑。

最小验证：在 `services/api` 执行 `go test -run 'Test.*MockScenario' ./...`。测试覆盖配置边界、通过 API 运行两个 HTTP 场景、采样和快照，以及拒绝跨场景严格对比。
