# 历史复跑与分档报告

新建 Mock 实验时可选择默认演示、正常（`baseline-v1`，160 ms）或变慢（`slow-v1`，420 ms）。选择在创建时写入配置。切换到 OpenAI 兼容目标会清除 Mock 场景。

工作台历史列表中，终态 Mock Run 的 **按配置复跑** 会向 `POST /api/v1/runs/{id}/rerun` 发起请求。服务端按旧 Run 快照和当前权限、配额启动新 Run。成功后进入新 Run 的监测，刷新账户配额，可刷新页面恢复正在运行的记录。遇到配额等错误时历史页会显示错误。真实 API Run 继续通过本地 Runner 的授权流程发起。

私有报告展示快照场景、Runner 版本、并发档位、RPS 上限、每档配置时长、预算、单请求超时和阈值。分档表展示完成样本数、P95、错误率、实际完成吞吐和达标、超限、样本不足三种判定。完成吞吐按观测时间计算。严格基线下拉仅列出相同场景和版本的成功 Mock Run，具体配置和样本有效性仍由服务端校验。正常与变慢应分别打开各自报告，保留两份快照。

验证命令在 `apps/web` 下执行 `npm run lint` 和 `npm run check`。可通过创建固定延迟 Mock → 查看报告 → 返回工作台 → 按配置复跑检查完整流程。复跑会创建新 Run，历史报告保持可读，普通公开分享继续使用原来的脱敏数据。

回滚时部署上一版前后端构建。此处没有数据库迁移。旧构建不能按新场景复跑，已有运行记录可保留；需要保留新场景行为时，回滚前先导出实验依据并保留数据库备份。
