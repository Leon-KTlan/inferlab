# 毕设版操作与回滚

## 本地启动

依赖 Go 1.24+ 和 Node.js 22。从仓库根目录执行：

```bash
make web-install
make api-run
```

另开终端运行 `cd apps/web && npm run dev`，打开 Vite 输出的地址。也可按根 README 的容器方式打包运行；本机体验使用 `INFERLAB_APP_ENV=local`，staging 使用独立数据库、HTTPS 和登录配置。

## 答辩演示

1. 新建 Mock 实验，选择“正常 · 160 ms”。可用单档并发上限 4、每档 4 秒、8 req/s、请求预算 100、超时 1000 ms、P95 阈值 250 ms、错误率上限 5%。查看分档报告中的配置快照、样本量和判定。
2. 选择“变慢 · 420 ms”，其余参数保持一致。查看同一阈值下的结果。如果现场资源不足导致样本不足，按报告提示延长阶段。
3. 返回工作台，在旧记录旁点击“按配置复跑”，新 Run 会进入监测页。核对两次配置快照一致，同时保留两个 Run ID。
4. 用事先保存的逐请求数据和 P95 图表说明正式实验。配置和复现命令见 [实验结果](RESULTS.md) 和 [实验复核工具](04-experiment-tool.md)。

## Staging 与回滚

部署步骤沿用 [staging 运行手册](../../specs/007-staging-runbook.md)。发布前记录当前镜像、备份 SQLite，并确认各环境使用不同的数据和密钥。发布后验证健康检查、登录，以及固定 Mock 创建、报告、按快照复跑。

本改动无需数据库迁移。回滚时恢复前一版匹配的前后端构建，保留新运行的源数据库备份。旧版可读取历史汇总，但旧 Mock 执行器不认识固定场景。若已创建固定场景模板，应停止用旧构建执行这些模板；需要验证旧构建时使用独立数据库，或按 staging 手册经人工确认后恢复发布前备份。回滚后再执行健康检查和默认 Mock 闭环。
