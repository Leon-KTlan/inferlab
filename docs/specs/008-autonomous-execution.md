# 无人值守 AI 执行规范

状态：`accepted`

## 目标

让后续 AI 能在根代理的任务分工下持续完成可验证的工程工作，减少等待人工回复的时间，同时把 token、权限和发布风险控制在可审计范围内。

## 执行循环

每个任务按以下顺序推进：

```text
读取规则和当前状态 -> 写出任务边界 -> 实现 -> 最小相关验证
-> 根代理审查 -> 提交 PR 或更新现有 PR -> 记录证据和剩余阻塞
```

任务分工必须包含：目标、文件边界、验收命令、风险、依赖和停止条件。AI 应优先完成不依赖外部凭据的工作；等待凭据时继续处理文档、测试、模拟环境和代码审查。

## 并行和模型选择

- 根代理是唯一的任务调度者和最终合并判断者。
- 只有文件边界互不重叠且可以独立验收时才并行启用 AI。
- 简单检索、格式化和局部测试使用低成本模型；架构、安全、数据迁移和发布审查使用高推理模型。
- 同一里程碑最多安排一次独立审查；修复后只运行受影响的验证集合，除非风险要求扩大范围。
- 子代理不得回滚其它代理的提交；发现边界冲突时停止写入并报告。

## Token 和时间预算

- 先读取索引、规则和相关文件，再进行最小搜索；不重复倾倒完整文件和长日志。
- 每个子任务先完成一个可验证闭环，再决定是否扩大范围。
- 连续两次验证没有新增信息时，停止重复测试并记录证据。
- 外部服务不可用时，不反复重试；转做独立任务并留下阻塞原因。

## 无人值守允许范围

可以自动执行：本地构建、单元/集成/浏览器测试、依赖检查、文档更新、PR 提交、staging 发布、健康检查、日志检查和已验证的应用回滚。

必须停止并等待人工确认：删除或覆盖生产数据、删除实例或 DNS、覆盖唯一备份、写入支付或云账号密钥、启用未审计的真实 API 压测、合并高风险 PR，以及无法证明可回滚的基础设施变更。

## 交接记录

每个完成的任务只报告以下内容：

1. 改动文件和行为摘要。
2. 实际执行的验证命令及结果。
3. 未解决风险、外部依赖和下一步。

没有 staging 证据的功能保持“未完成”状态；缺少凭据或权限属于阻塞，不应伪造成功。
