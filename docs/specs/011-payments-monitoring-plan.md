# 正式支付、监控和公开运营后续计划

状态：draft，未实现、未开通、默认关闭。本文件不代表获得商户资格或发布许可。

## 目标与边界

为下一批提供可审查的真实接入条件，继续沿用 Go/SQLite 单实例。当前没有订单、支付回调、付费权益或定时真实目标探测；不得展示假支付按钮或用前端跳转授予权益。邀请测试仍须 staging 验证。

## 支付依赖和拟议流程

后续先使用 alipay-aipay skill 核验实际签约产品和当前接口，确定商户主体、产品开通、应用身份、正式/沙箱环境、证书或密钥管理、回调域名及退款权限；未核实前保持关闭。环境只列变量名：`PAYMENTS_ENABLED`、`ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`、`ALIPAY_NOTIFY_URL`；最终变量和证书模式以核验结果决定，当前应用不读取这些变量。

拟议 API 是 `POST /orders`、`POST /payments/notify`、`GET /reports/{id}/premium`，尚不存在。订单金额用分的整数、产品/价格服务端固定；数据库订单状态与权益独立，支付通知验签后核验商户、应用、订单、金额和币种，必要时查单，再通过唯一交易号及订单事务幂等授予权益。重复/乱序/重放通知不重复授权。返回页只能展示服务端查单状态。退款、关闭、账单对账和人工补单必须先定义可审计规则。

验收需要真实沙箱或正式低金额交易证据、验签失败/金额不符/重复通知/查单超时/退款/跨 owner 覆盖。禁止伪造成功回调；切换正式环境需独立审查、备份和可禁用开关。回滚只关闭新订单入口，仍须处理在途通知与对账，不能删除支付账本。

## 监控依赖和拟议接口

先确定 staging/production 域名、HTTPS、实际代理拓扑、独立数据库/备份位置、指标保留期和人工告警渠道。`/healthz` 只验证进程和数据库；未来增加受保护的聚合指标（任务状态、延迟、预留量、401/403/429/5xx、数据库错误、磁盘/备份时效），禁止用户名、owner、endpoint、模型、cookie、请求体、诊断正文或凭据成为标签或日志字段。当前未实现指标导出或通知发送。

主动探测仅对逐项授权目标执行，必须约束并发、RPS、请求数、总时长和费用；不复用匿名浏览器授权作为持续授权。监控不得自动发真实供应商请求。外部告警发送需明确收件人和授权，验证时使用专用测试渠道。

## 发布门槛

真实依赖清单：staging 配置权限与访问地址、商户资格/签约、沙箱身份、正式证书管理、支付回调公网 HTTPS、对账与退款流程、监控服务/告警接收人、数据库备份和恢复演练、真实 API 授权/预算。缺项记录 BLOCKED，继续本地独立事项。

公开运营前验证注册限流在反向代理下的共享 IP 行为、可撤销会话、跨账户隔离、配额/认领并发、公共报告白名单、删除和迁移回滚；再完成支付与监控的独立验收。没有这些证据不得宣称上线。
