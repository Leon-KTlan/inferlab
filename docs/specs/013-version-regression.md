# 版本回归体检

状态：本地实现，待 staging 验收。

目标：从一份私人报告保存基线，复用其不可变实验快照，比较候选 Run，并按基线 SLO 判断本次采样。

- 基线仅保存 Run ID 和当前账户范围在本浏览器内。报告数据仍由服务端按当前身份读取，删除报告后需重选；不跨设备同步。
- Mock 从原实验启动，沿用登录、配额和取消。OpenAI 兼容目标预填原配置，但清空密钥并要求重新确认授权，再走本地 Runner；平台不发第三方推理请求。
- 对比沿用同账号、同来源、同软件版本、同目标、同负载及 SLO 快照约束。两次都须成功、覆盖所有阶段且每阶段至少 20 个完成样本。达标要求候选所有阶段的 P95 和错误率均不超阈值。样本不足或条件不匹配没有达标结论。
- 真实 Runner 指标为客户端回传，软件版本为现有 Run 标签，不证明供应商后端版本相同或不同；Mock 不代表线上性能。首版没有自动发布、定时探测、多基线管理或新表。

验收：Go 比较测试覆盖混合来源、版本与目标不匹配、不完整样本及阈值边界；浏览器 smoke 覆盖保存、刷新、一键复测、判断和切换隐私身份。回退镜像即可撤下功能，无 schema 迁移。

线上邀请试用：以 PR #8 为基线，按 [staging 手册](007-staging-runbook.md) 配置独立数据库、部署密钥、域名和 HTTPS。用测试通知接收方验证告警与恢复，并在隔离实例演练备份恢复。先邀请 3–5 位开发者，观察首次报告和下一次复测，无需等待正式收款。缺少域名或 staging Environment Secrets 时仅做本地验证。
