# AI 协作和交付流程

状态：`accepted`

## 任务生命周期

```text
需求 -> 规格决策 -> 任务拆解 -> 单一所有者实现 -> 测试
-> 根代理审核 -> PR/合并 -> staging -> 发布或回滚
```

每个任务必须有：目标、输入、文件边界、验收命令、风险、依赖和停止条件。代理完成后只报告结论和证据，不重复倾倒完整文件内容。

## AI 调度

- 根代理按需启用其它 AI，优先串行完成有依赖的任务。
- 可并行任务必须拥有不重叠的文件边界；禁止多个 AI 同时改同一个核心模块。
- 审查 AI 只给出可执行问题和证据，不无理由要求重构。
- 发现规格冲突时暂停实现，先更新 spec 和决策记录。

## Token 控制

- 先做最小相关搜索和测试，再扩大范围。
- 例行任务使用低成本模型；复杂架构、安全和发布审查才使用高推理强度。
- 一个里程碑最多一次独立审查；重复问题不重复跑完整测试。
- 代理输出控制在短摘要、文件列表、命令结果和风险清单。

## Git 和发布

代码、部署、安全和迁移默认走 PR；纯文档小变更可以随相关提交合并。生产发布前必须具备 staging 证据、备份和回滚步骤。可回滚的普通发布可以无人值守执行，破坏性基础设施操作需要人工确认。
